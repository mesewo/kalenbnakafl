# Project Note — Kalenbnakafl

Updated 2026-10-24. This note describes the repository as it exists today; roadmap goals and unverified deployment claims are excluded.

## Project

Kalenbnakafl is a website and staff workspace for a community NGO. It provides public news, events, media, contact and volunteer pages, with a role-based dashboard for content, users and volunteer contribution management.

## Current implementation

- **Web:** Next.js App Router, React and TypeScript. Public routes include home, about, blog and article detail, events, contact and volunteer pages. Blog and event lists call the paginated API. Pages use the current client/server component mix; this is not a claim that all public content is server rendered or statically generated.
- **API:** Go, Gin and PostgreSQL. SQL queries are generated by sqlc; Goose migrations are embedded and applied at startup when configured. Authentication uses short-lived JWT access cookies and rotating refresh cookies, with role checks against the database.
- **Roles:** admin, editor, user and volunteer, plus unauthenticated guests. Admin/editor content operations are under `/api/staff`; user and volunteer management routes are admin-only under `/api/admin`.
- **Media:** allowlisted file types are content-sniffed and stored under random names through a local storage interface. Public media URLs support byte ranges and use restrictive response headers.
- **Operations:** Docker Compose runs PostgreSQL, API and web services. Health and readiness endpoints are present. The backend GitHub Actions workflow runs migration round-trip, sqlc parity, build, vet and Go tests against PostgreSQL.

## Verified quality and current limits

The repository has Go tests, including PostgreSQL-backed integration tests, plus a backend CI workflow. The route authorization suite checks every API route registered by `routes.SetupRoutes` against guest, user, volunteer, editor and admin expectations. The front end has lint, TypeScript and build scripts; there is no front-end test or end-to-end test suite in the repository.

There is no verified public deployment or live demo URL recorded here. The project does not currently implement online payments, membership workflows, volunteer applications, event signups, contact inbox/status management, email notifications, or a documented OpenAPI specification. A language switch or complete UI/content translation feature is not present in the current front end. No coverage, Lighthouse, image-size or CI-duration metrics are claimed.

## Architecture choices

- Separate Next.js and Go services with PostgreSQL for persistence.
- HTTP-only SameSite=Lax cookies, access-token role rechecks, refresh-token rotation, origin validation for cookie-authenticated writes, and IP/email-aware in-memory rate limiting.
- Numbered schema migrations rather than an `init.sql`; optional development seed data is separate.
- Local disk behind a storage interface; object storage is not implemented.
- Compose provides local orchestration. A production reverse proxy, deployment pipeline and operational runbook are not claimed as complete.
